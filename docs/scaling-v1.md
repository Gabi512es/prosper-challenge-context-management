No retry occurred. Time-to-first-token combines provider/network/client scheduling time: these logs do not separate server queueing, prefill, network delay or event-loop stalls. There is no STT/TTS work in these text runs. No runtime change is made from this diagnosis.

## Deterministic expansion and invariants

Implementation: backend/evals/catalog_expander.py. Version `catalog-disjoint-v1`, fixed seed `20261109`. Hash-ranked name pools are stable across processes and Python RNG implementations. Factors are total entity multipliers, including originals, and larger factors contain the smaller factors as record prefixes.

Every original record and policy remains unchanged. Added records form disconnected copies: synthetic providers reference only synthetic sites and synthetic appointment types. Ordinary sequential IDs extend each existing namespace. New fictional research-service names and provider/site names avoid the original catalog and reserved DEV names; no repeated token padding is added. Clinical fields, hours, capabilities, durations and eligibility flags follow their copied templates. Original orphan types stay orphaned; no catalog repair occurs.

This is an irrelevant-distractor/capacity benchmark, not a clinical-realism, close-name adversarial or same-service fan-out benchmark. Availability fixtures are not expanded: they remain each scenario’s complete universe. Unscoped facets and invalid-filter valid-value lists may grow. Python lookups may grow with catalog size. Do not promise constant tool latency or constant response size for every query.

The original catalog git-blob pin is verified by load_dev_scenarios before generation. Derived snapshots have separate version/seed/source/output hashes and manifests; no catalog.blob_sha in a scenario is changed. Unit tests check all original details/search results, protected unknown names, original provider/type relations, all 12 DEV fact-card core outcomes/slots, and the positive booking fields at x50. These structural tests do not predict LLM pass rates.
